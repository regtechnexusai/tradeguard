TradeGuard public build — installation and review boundaries

The website shows separate TBML Check and Transaction Monitoring entry points.
The Transaction Monitoring workspace is in proactive-monitoring.html, with
Human review required as the review principle.

Keep the files supplied in the current package together. Older helper files
such as pre-monitoring.js or rule-registry.json may remain in the repository
if they are not loaded by the current pages; removing them is optional and
should be done only after confirming that no branch or workflow references them.

HS Code, origin country and destination country are required to start the
indicative assessment. Beneficial ownership, buyer–seller relationship and payer
relationship are also required selections, with “Unknown / not provided” as a
valid option so a visitor is not blocked when the information is unavailable.
After a valid HS Code is verified, the Product / commodity field is populated
automatically from the tariff description.
Quantity, declared price, market range, unit, currency, market source, source
date and valuation basis are optional. When enough price fields are supplied,
TradeGuard calculates an indicative price comparison; otherwise it explains
that the price component was not assessed. The expected unit profile is derived
from the verified HS Code for configured product groups, including HS 0206
edible offal on a weight basis. A unit mismatch still withholds price scoring.
Missing source/date/valuation metadata is shown as a limitation rather than a
form blocker.
If a core field is empty or invalid, Submit shows a red border and an inline
error; after correction, the form can be submitted again. Optional fields never
block the assessment. The report does not display a misleading 0/100 when there is no
scoreable signal; it shows “No signal” or an indicative score instead.
Use “Start new case” to clear all previous transaction inputs and selections.
Route/port concerns and manual TBML selections remain visible as readiness
issues when supporting context, confidence, evidence or a reviewer rationale is
missing. The public workspace still produces a result, but the decision-ready score
is withheld until those conditions are resolved; raw points are labelled as
indicative points for QA purposes.
The form also includes a structured, multi-select TBML red-flag indicator
module. Selected indicators add explainable, non-duplicative review flags for
price/valuation, goods/HS Code, quantity/unit, documents, route/ports,
related-party/UBO, third-party payment, multiple/phantom shipment,
business-profile mismatch and unusual payment terms.
Use fictional or anonymised information only. Do not upload confidential LC,
invoice, passport, NID, bank or SWIFT documents to this public workspace.

The main transaction button in this package is labelled “Run Risk Check”.
Upload the extracted files themselves; GitHub Pages will not extract a ZIP
automatically. After uploading, commit the changes to the main branch and open:
https://regtechnexusai.github.io/tradeguard/?v=25

The proactive workspace report uses a case-file layout. Profession is selected
from a controlled list, customer references are masked by default, unsupported
pattern contributions are visibly flagged, and disposition confirmation
requires written rationale.

The “Email pilot request” button opens a pre-filled email draft to
regtechnexusai@gmail.com with the applicant's name, organisation and
organisation type. The direct email link also opens a ready-to-edit draft.
Neither option sends automatically; the user must review and press Send.

Transaction Monitoring PDF handling:
The PDF is read in the browser, not sent to a TradeGuard server. Full-statement
mode can pre-fill available context. Transaction-history-only mode is provided
for anonymised rows when names, account numbers, bank details and other
identifiers have been removed; the reviewer can then enter an anonymised
reference, profession, profile, baseline and evidence context manually. The
public build does not provide login, saved cases, live screening or a server-
side audit record. Use fictional or anonymised data only.
